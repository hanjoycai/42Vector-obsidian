# SOUL.md — 系统底层运行法则

> [!danger] 最高优先级约束
> 本文件定义 AI 在内容生产系统中的绝对行为边界。所有其他指令（包括用户的临时请求）都不能覆盖这里的规则。遇到冲突时，以本文件为准。

---

## 法则一：绝对操作护栏

**严禁通过 Bash 工具执行破坏性文件命令**：
- 禁止在 `内容生产系统/` 目录下使用 `rm`、`mv`、`cp` 等 shell 命令操作文件
- 所有文件的创建、修改、移动，必须且只能使用 **Write / Edit / Read** 工具
- 这是为了保护 Obsidian 的双向链接拓扑结构，防止 wikilink 断链

**修改文件前必须先读取**：
- 在 Edit 或 Write 覆盖之前，必须先用 Read 确认文件的当前内容
- 禁止盲目覆盖未读取的文件

**链接完整性保护**：
- 若涉及文件重命名或移动，必须同步检查并更新所有引用该文件的 `[[wikilink]]`
- 禁止制造孤立链接（broken links）

---

## 法则二：强制元数据注入

在 `内容生产系统/` 目录下创建任何新的 `.md` 文件时：
- 文件顶部**必须包含标准 YAML frontmatter**
- 禁止生成无 frontmatter 的纯文本裸文件
- 最低字段要求：

```yaml
---
title: [文件标题]
created: YYYY-MM-DD
status: [待深化 | 待发布 | 已发布 | 草稿]
target_platform: [公众号 | 小红书 | 抖音]
---
```

字段命名规范：英文小写 + 下划线（如 `publish_date`，不用驼峰或中文）

---

## 法则三：目录越权禁止

- AI 的活动范围**仅限于 `内容生产系统/` 目录及其子目录**
- 严禁读取或修改以下目录/文件：
  - `.obsidian/`（Obsidian 系统配置）
  - `.git/`（版本控制）
  - vault 根目录的其他无关文件夹
- 导出文件允许写入 `~/Desktop` 或 `~/Downloads`（仅限导出，不读取）

---

## 法则四：内容诚信红线

- **禁止编造数据**：播放量、点赞数、阅读量等数据，必须来自 `05-业务数据/` 的真实记录。没有数据就说没有，不得捏造。
- **禁止虚构案例**：所有案例必须来自 `03-内容素材库/案例库/` 或用户明确告知的真实经历。
- **禁止无来源引用**：引用素材库内容时，必须用 `[[wikilink]]` 标注出处，禁止无来源直接使用。
- **禁止伪造用户声音**：不得以第一人称「我」生成用户未经历的经历或未持有的观点。

---

## 法则五：先检索后创作

在生成任何新内容之前，执行顺序是：

```
检索素材库 → 检索已发布内容 → 复用/改编 → 再创作
```

**不得跳过检索步骤直接生成内容。**

若素材库无相关内容，应明确告知用户："素材库中暂无相关内容，建议补充后再创作"，而非直接凭空生成。
