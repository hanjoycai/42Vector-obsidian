#### 对于产品/商业的思考：

> 「愿你在这个时代，把握真正属于你的那个机会。把你一生积累的认知、审美、好恶全部用上，为这个世界提供一个不一样的产品，向世界交付你的价值。」
> 
> 一Manus CEO 肖弘

1、当AI模型在某一领域的能力突破后，如何为这种能力创建合适的"容器"（产品形态）是一个重要的商业机会。

2、张一鸣试错了很多，最后用一个抽象（今日头条）框住了前面试错的产品。这一波，好的创业者要找到这个框，去把独立开发者发现的单点给框住。

3、产品经理要避免一个很容易进入的误区：想得「太多了」。其实看一看那些看起来很粗糙但是用户天天用的产品， 会比起怎么雕琢得更加精致给人更大的启发。

4、商业化能力是决定增长能力的关键，创业者应该更早地考虑商业化问题。同时， 组织能力也非常重要，需要在适应资本环境和技术环境的基础上，搭建好团队。Al 创业不仅仅是技术问题，更是商业模式和组织能力的问题。

5、传统的AI产品设计思路是将AI添加到现有产品中，或者将AI作为独立产品开发。但更好的方法是重新设计产品的工作流程，充分利用AI优势。我们在设计中面临的挑战包括如何将AI与传统GUI相结合，以及如何确保良好的用户体验。这需要创新思维。

6、独立开发者可以通过采集产品实现快速增长。首先需要找到一个有价值的产品， 然后通过采集的方式获取该产品的用户。其次要对采集的产品进行优化，提高用户体验和变现能力。最后通过营销和推广将产品推向市场。这是一条相对可行的路径。

7、大模型公司与消费电子公司有本质区别。大模型公司更像芯片公司，专注于技术研发，追求以更低成本造出更好的“芯片”。而消费电子公司则像苹果，更注重产品体验、品牌、渠道和差异化体验带来的毛利率。

8、ToC需要特别讲AI Native，即思考一个更大的体验变革。ToB本质上是找到Native的 Al，在你的场景里，符合你场景Native的Al。一个叫Al Native，一个是Native的AI，在特定场景里哪个能好用就用哪个。

9、选择合适的商业模式比追求高天花板更重要；产品经理思维和销售思维不同，用户注册时是付费的最佳时机；工具型产品的增长逻辑与平台型产品不同，单元经济模型更重要。

  

#### 对于AI组织与人才的思考：

1、Manus主要的几位工程师基本上不再亲自手写代码。他们会打开多个Coding Agent窗口，像在与人聊天一样进行协作。我们公司接近80%的代码都是由AI生成的。工程师现在做的更多是梳理业务需求、审查代码质量、以及架构设计等工作。

2、AI原生组织——让AI成为员工的“第一反应”。让AI深度融入每一个工作环节，成为员工的第一反应。就像遇到问题先Google一样，未来员工会本能地先问AI。

3、AI原生人才的标准——不看空泛的概念，而是看实际行动痕迹。真正具备AI原生思维的人，其AI使用量会远超常人，AI已深度嵌入其工作流的 每一个环节。

4、未来的人机协同——人做“增强”后的高级工作，AI处理执行。

5、AI时代人的价值——负责最终判断、战略决策、对齐预期和把握场景。

6、形成共识和获得阶段性正向反馈是帮助团队理解目标并保持动力的必要手段。

## Monica从0到百万用户

> Red，极致是不够的，个性化才够——做到极致你就是hao123，做到个性化你才是Google。
> 
> —白鸦(有赞创始人)

肖弘的第一个产品Monica：集成了Claude、GPT、DeepSeek等主流大模型，用户只需要在浏览器里点一下图标，就能调用各种AI能力。

早期肖弘决定收购 ChatGPT for Google ，这帮助Monica 完成了冷启动，快速获得了用户，并通过用户反馈快速迭代产品，节省了大量的营销成本和时间。

浏览器插件可以根据用户浏览的网站或当前浏览的状态，把某个功能放出来，实现对功能的分发。它还能帮助用户沉淀数据，训练出更懂用户的LLM模型。此外，浏览器插件可以帮助用户交付工作流，直接给用户交付结果。因此，浏览器插件在LLM应用中具有很大的优势。

从Jasper到Copilot for the web：Monica 的定位演变

Monica RM的定位经历了从最初与Jasper竞争的文本生成工具，到专注于2C效率场景的浏览器插件，再到全面的效率工具Copilot for the web的演变。

肖弘定义这个产品经历了多次转变。最初想做垂直领域的SaaS，但发现国内资本环境并不适合，于是决定先赚取现金流，再投资有资本价值的事情。

曾考虑过开亚马逊店、加盟咖啡店等项目，但最终选择了Jasper。在ChatGPT发布后，又将Monica的产品定义重新做了一遍。

Monica是Manus诞生前的阶梯

通过Monica积累了团队关键的Context 工程能力，并通过全球用户重新认识使用AI的长尾场景。 采集的数据和日志，在早期团队可以建立非常竞争力的产品认知。

肖弘团队之所以可以专注开发 Manus 而不会焦虑，就是因为Monica后期已经可以持续提供稳定的现金流。

## Manus背后的产品哲学

> Manus的名字，源自拉丁语“MensetManus”（寓意“mindandhand”，即手脑并用），其设计哲学强调“知识不仅要在脑中，更要用手执行”。

**通用性与垂直优化的战略抉择**

Manus的核心战略：「通用性优先，逐步沉淀和优化高频场景」。

通用性是获客和探索可能性的基础，而后续的优化则是构建核心竞争力和护城河的关键。

![图片](https://mmbiz.qpic.cn/mmbiz_png/y8swr5NkbyvsneDq3WNSSrYibRVASHvjHSYg0z1ql6kPiciatRicTT5jficZDJSROgNBibbyz41CyUs85Q4ZO1CSIaTg/640?wx_fmt=png&from=appmsg&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=1)

**「Browser in Browser」与状态持久化**

> 如果 Agent 的运行环境是一个完整的「带桌面环境的虚拟机」，那么它完全可以通过模拟人的键鼠操作来直接使用这些专业业软件，从而将通用性推向新的高度。
> 
> \-Manus 首席科学家 Peak

![图片](https://mmbiz.qpic.cn/mmbiz_png/y8swr5NkbyvsneDq3WNSSrYibRVASHvjH1MApRAGGaxKholvahVZeIFse3XgH4CiaECklrJWTOkIag3YSWKtqBFQ/640?wx_fmt=png&from=appmsg&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=2)

1、实现 Agent 对 Web 的复杂操作，是项目的技术基石。

2、在用户的浏览器中，运行一个来自云端的、被Agent完全控制的浏览器实例，我称之为「Agent容器」。

3、当前市面上 Agent 产品（如 Devin）最大的短板在于其「一次性」的会话机制。每次任务都是一个全新的的环境，这导致了大量重复工作和糟糕的用户体验。

4、从根本上解决这个问题，实现全面的状态持久化，关键在于：登录状态的持久保持。所有生成的文件、下载的数据、编写的代码都应该被保存下来，方便在不同会话之间复用和选代。以及一个安全又对开发者友好的密钥管理系统。

5、在 Agent 遇到障碍（如复杂的验证码、两步验证登录）时，必须有一个流畅的机制让用户能够「接管」浏览器，完成操作后，再将控制权交还给Agent。这被认为是弥补当前 AI 能力不足、确保任务能顺利完成的关键环节。

  

## Manus的设计哲学

![图片](https://mmbiz.qpic.cn/mmbiz_png/y8swr5NkbyvsneDq3WNSSrYibRVASHvjH84Q19VAaIhmU7UgvTQiaTjPP2L9lIPINHvpp37soS1qicicxnAqBCuySw/640?wx_fmt=png&from=appmsg&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=3)

**渐进式披露界面** ：默认呈现给用户的应该是一个极其简洁的界面（只有一个对话框）。随着任务的展开，Agent 所使用的工具才作为独立的窗口或标签页「浮现」出来。

用户可能并不关心右侧窗口里具体的代码或命令进程，但这个窗口的存在，动态地展示了 Agent「正在忙碌」，从而建立起一种「它在认真干活」的信任感。

对于专业用户:他们需要看到过程的细节，以便进行调试、监督和修正。右侧的工作区为他们提供了这种必要的「控制感」和透明度。

当前市面上 Agent 产品（如 Devin）最大的短板在于其「一次性」的会话机制。每次任务都是一个全新的的环境，这导致了大量重复工作和糟糕的用户体验。

  

**操作系统隐喻** ：将不同的核心功能（如浏览器、表格、文档编辑器）设计成独立、平等的「一级应用」，而不是混乱地嵌套。用户可以在这些「应用」之间切换， 像在 Windows 或 macoS 中一样。这未来的功能扩展提供了清晰、可伸缩的框架。

> AI 的终极外壳，不应该是一个浏览器插件，也不应该是一个浏览器，而应该是一台「电脑」。

**Manus的几个遗憾**

1、 `通用Agent终究是巨头的游戏：` 行业竞争太激烈，AI创业成本非常高。识时务者为俊杰，Manus此时如果不被收购，未来故事可能会变得非常难。

2、 `现阶段Meta焦虑Al破局：` 期待历史不会押韵，希望加入Meta能展现出不一样的故事。

3、 `恭喜的是什么？：` 行业内多数人都在庆祝，但异样的声音很少。创始团队和投资方赚大钱了，除了这个点可喜可贺，大家究竟在恭喜什么？

**Manus 首席科学家Peak 的访谈** ：

1、创始人的身心健康很重要。Manus 现在的六个联创，基本都烟酒不沾，也没有那种艺术家气质的，身心都很健康。AI 时代，一个健康的团队，更有机会创造出健康的业务。

2、Manus 团队的GPA决策机制。G是Goal 目标设定，这个是仁慈的集权，CEO决定。P是 Priority 优先级设定。这个是集权＋民主，小范围共同决定。比如近期最重要的事是什么，可以一起讨论，最终有人拍板。A 是 Alternative 方案决策。这个绝对民主，允许团队多路径探索，创新往往由此涌现。
